# Language Suite Next Steps

## Current State
- Direct eval inside class field initializers now inherits the enclosing `super` binding even when the base prototype lacks the requested property: `super.prop` now returns `undefined` rather than throwing, and regression tests cover eval-produced arrow functions assigning fields.
- Activity-based regression tests exist for the failing `Expressions_class_elements` shapes (instance/static/eval arrow cases) so we can iterate without running the full Test262 language suite every time.
- Generator functions now preserve previously supplied resume values when replaying class member computed names, so `yield` inside class accessor names works in both the parser (computed `in` expressions) and the runtime (see the updated `ClassComputedAccessorTests`). The Test262 suites still contain numerous failures (e.g., statement forms hit generator IR gaps and static/private accessor cases fail earlier in evaluation), but the new infrastructure unblocks further fixes.
- Class expressions whose binding names spell `await` (including escape sequences) now parse correctly in strict script goals; the `class-name-ident-await*.js` Test262 cases both pass.
- Generator iterator objects inherit from their function prototype (or `Object.prototype` fallback) so computed property names that call generator functions convert to property keys instead of throwing `TypeError: Cannot convert object to primitive value`.
- `Array.prototype.concat` now builds its result via `CreateDataPropertyOrThrow`, samples spread lengths through `LengthOfArrayLike` with realm-aware `ToLength` coercions, and refuses revoked proxies before touching their constructors, so the `array-like-to-length-throws`/species tests now throw the right TypeErrors while respecting `@@isConcatSpreadable`.
- Revoked proxies now trigger real JavaScript `TypeError` instances as soon as `Array.prototype.concat` inspects their constructors or `@@isConcatSpreadable` hooks, and double-proxy receivers reuse the original realm’s species constructors, so the `create-proxy`/`create-revoked-proxy`/`is-concat-spreadable-proxy-revoked` buckets pass.
- Class static blocks are parsed and executed (interleaved with other static elements), so `static-init-await-reference.js` now reaches runtime and observes `await` as an identifier within the block’s scope.
- Property assignments now reuse the active private-name scope when resolving `#name` keys, so static/private setters throw `TypeError` when invoked with receivers that lack the defining class’s brand (e.g., `private-static-setter-multiple-evaluations-of-class-realm.js` now passes).
- Parameter default expressions (including static generator methods) can read the per-call `arguments` object because the binding is created before parameter evaluation for both regular and generator functions (`params-dflt-gen-meth-static-ref-arguments.js` now passes).
- Class heritage validation now calls `IsConstructor` before accepting the `extends` value, so extending async arrows (or other non-constructors) throws the mandated `TypeError` (`heritage-async-arrow-function.js`).
- Generator methods (instance, static, object literal, and statement forms) now create a dedicated parameter environment whenever defaults/patterns are present, and generator evaluation contexts carry the correct blocked-var set. The `scope-*-gen-meth-paramsbody-var-open.js` matrix (strict & non-strict) passes, confirming parameter defaults no longer see body vars/lexicals.
- `Array.prototype.some` now follows the spec’s array-like algorithm (including `thisArg`, TypeError checks, and arbitrary receivers), `%TypedArray%.prototype.some` is wired to the same helper, and the JSON object exposes the standard `[Symbol.toStringTag]`. The `Array_prototype_some` bucket dropped from ~380 failures to 76, with the remainder isolated to typed-array detach/`this` semantics.
- `Array.prototype.fill`, `Array.prototype.copyWithin`, and `Array.prototype.toSpliced` (plus `%TypedArray%.prototype.toSpliced`) now honor the spec-required default arguments and deletion semantics, so proxies observe the correct `has`/`delete` ordering and explicit `undefined` delete counts consume the tail. Regression tests pin the new behaviors.
- `%TypedArray%.prototype.fill` and `%TypedArray%.prototype.copyWithin` now exist on the shared typed-array prototype and mirror the array semantics (argument trimming, overlapping copies, and repeated detach/out-of-bounds checks). New regression tests cover default arguments, overlapping ranges, and the `undefined`-to-zero conversions for unsigned views.
- `%TypedArray%.prototype.reverse` swaps elements in place with the same detachment safeguards as the array version, and BigInt views reuse the typed array coercions so the new regression tests cover both numeric and BigInt flavors.
- `%TypedArray%.prototype.every` landed alongside regression tests for callback invocation order and `thisArg` binding, completing another chunk of the typed-array loop helpers.
- `Reflect.construct(Array, ...)` now falls back to the `%Array.prototype%` intrinsic from the NewTarget's realm when its `prototype` property is missing or non-object, so the `proto-from-ctor-realm-*` tests observe cross-realm prototypes (see the new regression in `AdditionalArrayMethodsTests`).
- `Array.from` now re-samples the source array-like `length` on each iteration and only counts successfully visited indices, so deleting elements mid-flight no longer produces phantom entries; the new regression mirrors the Test262 `elements-deleted-after` coverage.
- Strict global scripts mirror `var` bindings onto `globalThis`, so `"use strict"; var marker = 1;` writes through to the host global object and the regression in `StrictGlobalVar_BindsToGlobalObject` now passes.
- `Array.fromAsync` now walks async/sync iterables and array-likes, awaiting the source/mapping values, respecting constructor species, and rejecting via Promise semantics; the new AdditionalArrayMethods coverage exercises async generators and array-like promise values.
- `Array.from` now treats any provided `mapfn` (including `null`) as requiring a callable mapper, constructs `this`-provided constructors before the iterator is pulled, and tolerates iterator `return()` methods that produce primitives; the new AdditionalArrayMethods regressions prove the constructor ordering, callable validation, and iterator-close behavior.
- The `Intl` namespace object now exposes spec-facing scaffolding (`Intl.getCanonicalLocales`, `Intl.supportedValuesOf`, and the `[Symbol.toStringTag]` descriptor) wired through the new prototype/constructor generator; the helper currently returns a minimal calendar/time-zone set and still relies on the earlier CultureInfo-based canonicalization path, so the richer Test262 buckets remain open.
- `IntlUtilities.CanonicalizeLocaleList` now mirrors the spec’s array-like enumeration semantics: it coerces arbitrary objects via ToObject, samples `length` through `ToLength`, performs `HasProperty` checks before `Get`, and deduplicates canonical tags in insertion order, unblocking the DisplayNames locale-matcher tests that expect poisoned getters to be observed.
- Every Intl constructor now resolves locales through `StandardLibrary.ResolveIntlLocales`, their `supportedLocalesOf` methods share the same canonicalization helper, `Intl.Locale` stores canonical tags, and Intl.DurationFormat now brands instances so prototype methods can validate receivers.
- `Intl.getCanonicalLocales` matches the spec-required coercions: primitives other than strings now throw `TypeError`, `Intl.Locale` instances contribute their canonical `-u-` keywords, and the Unicode/Transform extensions are re-canonicalized (sorting keywords and applying alias replacements), so the entire Test262 bucket passes.
- `Intl.DisplayNames` now reports a Function.length of 2, its `supportedLocalesOf` helper mirrors the spec-required attributes, and its prototype relies on the shared `CanonicalizeLocale` helper for language parsing so the Test262 `intl402/Intl/supportedValuesOf/coerced-to-string.js` slice is unblocked.

## Next Iteration Plan
1. **Triage the remaining generator IR gaps** – revisit the `cpn-class-expr-*-yield` buckets (fields/accessors/static/private) and Annex B “contains supercall” shapes to nail down which AST patterns the current plan builder still rejects, then craft focused regression tests before extending the IR.
2. **Align compound assignment semantics with spec** – ensure property references are resolved exactly once, nullish bases throw `TypeError` before the RHS executes, and `with`/proxy/@@unscopables paths reuse the cached reference. Add regression tests mirroring the `language/expressions/compound-assignment/*` cases called out in `failing/languagetests.testsession`.
3. **Audit parser/evaluator helpers shared between eval + class fields** – in particular the `EvaluatePropertyAssignment` / `AssignmentReferenceResolver` paths – so private names, `arguments`, and `new.target` behave the same whether the initializer is literal or produced by direct/indirect eval.
4. **Lock down the species changes with tests and typed-array parity** – add regression coverage that exercises `@@species` overrides (`flat`, `flatMap`, `toSorted`, the typed-array copies, detach/resizable edge cases), and audit any remaining `%TypedArray%` “copying” helpers so both arrays and typed arrays share the same creation path and observable semantics.
5. **Finish the change-array-by-copy audit** – extend the new helper stack to the remaining `%TypedArray%` change-by-copy helpers (e.g., `toReversed`, `toSorted`, future `%TypedArray%.prototype.with` species paths) and add resizable-buffer regression tests so the “holes-not-preserved”/length-clamp Test262 buckets clear out for both arrays and typed arrays.
6. **Complete the remaining Intl internals** – now that everything funnels through `ResolveIntlLocales`, replace the `CultureInfo`-based canonicalization with the CLDR payload, expand `Intl.supportedValuesOf` so its value lists mirror the constructors we expose, and flesh out `Intl.DisplayNames`/`Intl.RelativeTimeFormat`/`Intl.DateTimeFormat` so they populate real option slots and can pass the intl402 Test262 buckets.
