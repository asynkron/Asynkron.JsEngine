# Widen unified bytecode production: conditional, optional-chain, and logical-assignment lanes

## Baseline
- Current main executes the full production binary operator set (`+ - * / % **`, `& | ^`, `<< >> >>>`, `== === !== !=`, `< <= > >=`, `in`, `instanceof`), `this`-based property reads, property-read+binary expressions (`this.x === v`), named/computed/spread call invocation, optional member **calls** (`box?.read(a)`, ADR 0289), non-spread construct calls, object-literal shorthand/name-inference/simple-computed-key, array spread in array literals, named compound property writes (`this.x += v`, all 12 operators), and `&&`/`||`/`??` short-circuit expressions fully inside `UnifiedBytecodeVirtualMachine` (no mixed execution).
- `&&`/`||`/`??` are backed by the **peek-semantics** jump opcodes `JumpIfShortCircuitFalse`/`JumpIfShortCircuitTrue`/`JumpIfShortCircuitNotNullish` (ADR 0293, rule 41): the VM peeks TOS without consuming it so the surviving operand is the expression result.
- Still declined before VM execution: ternary/conditional `?:` (needs a **consume-semantics** conditional jump distinct from the peek short-circuit opcodes), optional-chain property/element **reads** (`a?.b`, `a?.[k]`) under `OptionalChainDependency` (`JumpIfNullish` with `ReplaceWithUndefined` / `JumpIfShortCircuited`), and logical-assignment writes (`x &&= y`, `x ||= y`, `x ??= y`) under `PropertyWriteDependency`.
- Each `## Batch` below is a phase: all items in a batch run in parallel, and the next batch begins only after the current batch completes. Batch 1 lands the consume-semantics conditional branch the later lanes build on; Batch 2 lands optional-chain short-circuit reads to complement the already-admitted optional calls; Batch 3 composes the batch-4 compound-write boundary with the batch-5 short-circuit jumps.
- Every lane must keep the four coupled surfaces in sync per rule 41: the `UnifiedBytecodeVirtualMachine` execution arm, the `UnifiedBytecodeCompiler` lowering/gate, the `UnifiedBytecodeProductionEligibility` admit/decline gate (including `TryFindPrototypeOnlyOpcode`), and the focused eligibility + invocation tests.

## Batch 1 - Conditional (ternary) expression `?:`
- [ ] Add VM execution for a **consume-semantics** conditional branch that backs `?:`: the condition value is popped before branching (unlike the peek-semantics `JumpIfShortCircuit*` opcodes that back `&&`/`||`/`??`), exactly one arm is evaluated, and only the chosen arm's value remains on the operand stack. Provide backpatch support for both the condition jump and the unconditional join `Jump` at the end of the then-arm.
- [ ] Lower the expression-IR conditional shape to the new consume-semantics conditional opcode in `UnifiedBytecodeCompiler` (distinguishing it from the batch-5 peek remap of `JumpIfFalse`/`JumpIfTrue`) and admit the shape in `UnifiedBytecodeProductionEligibility` and `TryFindPrototypeOnlyOpcode`; keep optional-chain short-circuit (`JumpIfShortCircuited`, `JumpIfNullish` with `ReplaceWithUndefined`) declined under `OptionalChainDependency`.
- [ ] Add focused eligibility + invocation tests for `c ? a : b` with slot, literal, and `this`-property condition and arms, plus nested ternaries (`c1 ? c2 ? a : b : d`); assert the non-chosen arm is never evaluated (side-effect-once on the chosen arm) and that unsupported conditional shapes still decline.

## Batch 2 - Optional chaining property and element reads `?.`
- [ ] Add VM execution for the optional-chain short-circuit opcodes (`JumpIfNullish` with `ReplaceWithUndefined` and `JumpIfShortCircuited`) so `a?.b`, `a?.b.c`, and `a?.[k]` short-circuit the remainder of the chain to `undefined` when the base is `null`/`undefined`, preserving single-program operand-stack semantics and evaluating the base exactly once.
- [ ] Replace the `OptionalChainDependency` declines for optional property/element **reads** (the `IsOptional`/`ShortCircuitOnNullishTarget` `GetNamedProperty`/`GetComputedProperty` arms and the `JumpIfNullish`-`ReplaceWithUndefined`/`JumpIfShortCircuited` arms in `TryFindExpressionDecline`) with admits for the proven activation-resolved optional-chain shape; keep the already-admitted optional **calls** (ADR 0289) consistent and keep deeper/mixed and non-activation-resolved optional shapes declined.
- [ ] Add focused eligibility + invocation tests for `a?.b`, `a?.b.c`, `a?.[k]`, and short-circuit-to-`undefined` on `null`/`undefined` bases with a single base evaluation; assert non-optional chains are unaffected and unsupported optional shapes still decline under `OptionalChainDependency`.

## Batch 3 - Logical assignment `&&=`, `||=`, `??=`
- [ ] Add VM execution for logical-assignment to activation slots and activation-resolved named-property bases: read the current value, short-circuit on the operator's condition (truthy for `&&=`, falsy for `||=`, non-nullish for `??=`), and only then evaluate and store the RHS — reusing the batch-4 compound-write boundary opcodes (`GetNamedPropertyForCompoundSet`/`SetNamedProperty`) and the batch-5 short-circuit jump opcodes.
- [ ] Replace the `PropertyWriteDependency` decline for the logical-assignment shape (confirmed declined in batch-4) with an admit in `UnifiedBytecodeProductionEligibility` for the proven slot and named-property targets with a simple RHS operand; keep computed bases, optional bases, and deeper chains declined.
- [ ] Add focused eligibility + invocation tests for `x &&= y`, `x ||= y`, `x ??= y` on slots and `this.x &&= y` / `this.x ||= y` / `this.x ??= y` on named-property bases; assert the RHS is evaluated and stored only when the operator proceeds (no write on short-circuit) and that unsupported logical-assignment shapes still decline.
