# Asynkron.JsEngine Roadmap

_Last updated: 2026-06-09 (PRs #2750, #2755, #2758, #2761, #2768, #2772, #2777, #2783, #2787, #2788, #2795, #2804, #2805, #2814, #2816, #2855, #2858, #2862, #2897, #2898, #2900, #2908, #2930, #2931, #2932, #2941, #2946, #2948, #2949, #2950, #2951, #2952, #3116, #3118, #3122, #3123, #3138, #3142, #3195, #3201, #3203, #3207, #3208, #3209, #3480, #3484, #3485, #3486, #3488, #3505, #3528, #3529; follow-ups #2954, #2955, #3238, #3490, #3491, #3530, #3531, [agentmanual1780943196527007000](http://127.0.0.1:8787/issues/agentmanual1780943196527007000), [agentmanual1780943208911272000](http://127.0.0.1:8787/issues/agentmanual1780943208911272000))_

## Current State

Asynkron.JsEngine is a JavaScript engine for .NET with broad ECMAScript coverage. Execution runs through a multi-tier typed-AST evaluator rather than a single tree-walker: a `UnifiedBytecodeVM` as the target hot route, an `ExpressionProgram` expression-bytecode VM, a lowered statement-IR runner (`ExplicitExecutionPlan`), and an AST tree-walking bridge retained only as a correctness fallback. Recent work has concentrated on the typed-AST evaluator and allocation reduction in hot paths:

- Per-`FunctionExpression` caching of `SyncFunctionInvoker` static analysis (PR #2661, ~15% faster `forofiteration`).
- Skipping the redundant arguments guard in the simple-IR closure-activation fast path (PR #2646).
- `JsValue` struct adoption across numeric/string coercion paths — `ToNumericCore` and `ToJsStringFromObjectValue` (commit bd70ca63); the evaluation-pipeline `JsValue` migration boundary is recorded in ADR 0281 / rule 20 (PR #2651).
- Unified-bytecode production routing widened to label-dependent control flow (gh2679, ADR 0285): labeled statements, labeled loops, labeled block `break`, and labeled `break`/`continue` now route through the compiler-owned resolved-target path. The former label-specific decline bucket has been retired; unsupported driver topology now belongs to concrete driver-state or plan-shape gates.
- Unified-bytecode production routing widened to admit simple **object destructuring** driver shapes (`const { a, b } = obj`, optional identifier rest) via a VM-owned `ObjectDestructuring*` opcode family mirroring the array precedent; computed keys, defaults, and nested patterns still decline model-first. Decision recorded in ADR 0284 (issue gh2677).
- Unified-bytecode production routing widened to admit **synchronous spread calls** (`f(...args)`, `obj.method(...args)`, multi-spread, mixed positional+spread). Spread mask packed into existing `CallInvocationBoundary` operand; VM flattens spreads via `EnumerateSpread` helper preserving iteration order and side-effects. Optional calls, construct/super, and direct eval still decline. Decision recorded in ADR 0287 (issue gh2676).
- Unified-bytecode production routing widened to admit **optional member calls** (`box?.read(args)`, `box.read?.(args)`, `box[key]?.(args)`). Two new opcodes (`PrepareNamedOptionalCallTarget`, `PrepareComputedOptionalCallTarget`) encode the nullish short-circuit target in the high 16 bits of the operand; the VM checks nullish before proceeding and yields `undefined` on short-circuit. Receiver-as-`this` contract preserved identically to non-optional member calls. Decision recorded in ADR 0289 (issue gh2689).

- Unified-bytecode production routing widened to admit **synchronous non-spread construct calls** (`new F(...)`). New `ConstructInvocationBoundary` opcode invokes `[[Construct]]` with the constructor as `new.target`, mirroring the spec-conformant construct reference helper (`new.target` propagation, not-a-constructor `TypeError`, left-to-right argument order). Spread-onto-construct and member-target/non-simple constructs still decline. Decision recorded in ADR 0286 (issue gh2690).
- Unified-bytecode production routing now admits the first non-spread **super invocation** shapes. Derived constructors route `super(...)` through `SuperConstructInvocationBoundary`, and class methods route named/computed super-member calls through `PrepareNamedSuperCallTarget` / `PrepareComputedSuperCallTarget` plus `CallInvocationBoundary`. Spread super constructs and super property reads/writes/updates still decline before VM execution. Decision recorded in ADR 0307 (PR #2862).

- Unified-bytecode production routing widened to admit **`this`-based named-receiver chains and binary expressions**. `LoadThis`/`LoadNewTarget` base nodes are now accepted by the boundary-property-read classifier (`TryIsFirstBoundaryPropertyReadBinaryExpressionCandidate`), allowing call sites like `this.method(this)` and guard expressions like `this.prop === value` to compile through the unified route (commit `64a914f6`).

- Unified-bytecode resumable generator route **corrected for spec-conformant generator instances and iterator results**. Two correctness fixes: (1) `TryCreateUnifiedBytecodeGenerator` now resolves the generator function's own `.prototype` property via `ResolveInstanceGeneratorPrototype` so `g() instanceof g` holds; (2) `CreateIteratorResult` threads the `EvaluationContext` and sets `%Object.prototype%` on each `{value, done}` result, per `CreateIterResultObject`. Fixes Test262 generators `has-instance`, `prototype-value`, `Symbol.toStringTag`, and `GeneratorPrototype/next/result-prototype` (commit `69707f8d`).

- Unified-bytecode resumable generator route **gated on simple-identifier parameters**. Generator functions with destructuring, default, or rest parameters were silently skipping `FunctionDeclarationInstantiation` — parameter errors (e.g. `TypeError` for `*m([[x]]){}` called with `[null]`) were never thrown. `TryCreateUnifiedBytecodeGenerator` now gates on `HasOnlySimpleIdentifierParameters`, falling back to the runner path which evaluates `FunctionDeclarationInstantiation` eagerly. Fixes ~520 Test262 `gen-meth` destructuring regressions (commit `330c1eb0`).

- **AnnexB blocked-names HashSet skipped when body has no function declarations** (commit `8be3852f`, PR #2702). `CreateExecutionEnvironment` formerly allocated a `HashSet<Symbol>` on every non-strict function call to track Annex B B.3.3 var-scope hoisting. That set is only used by `HandleFunctionDeclaration`, which never fires when no block-level function declarations exist. Guarding on `hoistPlan.HasFunctionDeclarations` eliminates the allocation in the common case: `simplearithmetic` −37% (447→281 ms), `classdef` −43%.

- **`StringifyValue(JsValue)` overload added to `JsonHelper`; legacy `object?` path marked `[Obsolete]`** (PR #2704). `ConsolePrototype` call sites updated to use the `JsValue`-native overload directly. `TryGetObject(object?, ...)` in `StandardLibrary.Helpers` also marked `[Obsolete]`, advancing the JsValue migration boundary described in ADR 0281 / rule 20.

- **`docs/dreaming.md` expanded with shape/IC system, event loop lifecycle, performance SLOs, and active GC allocation budget** (commit `80514626`, PR #2698). Added: component 10 (Shape/IC — hidden-class layout, transition table, mono/poly/mega IC, IC invalidation); full event-loop lifecycle diagram distinguishing microtask drain from host macrotask scheduling; Performance SLOs section with measurable targets (startup latency, allocation per hot loop, microtask drain, Test262 failures, Tier 0 coverage); active GC allocation budget table with per-site Gen 0/1/2 targets and boxing-avoidance rules. Component numbers renumbered (DevTools → 12, Security → 13).

- **Array- and object-literal argument widening via span-based operand recognition** (commit `cf7d4924`, PR #2719). The compiler's span-walk now admits array-literal and object-literal expression arguments at call boundaries, closing the gap tracked in gh2705. ADR 0290 records the design; holes, spread, computed keys, and name-inference forms still decline model-first.

- **Object literal property shorthand in unified bytecode production** (PR #2738). Shorthand properties (`{ x }` equivalent to `{ x: x }`) are now compiled through the unified route. Rule 6 captured in PR #2739 establishes that `DefineObjectProperty` calls with `AllowNameInference` must be wrapped with `EnsureHasName` to preserve function-name signals for debuggers and `toString`.

- **10 missing binary operator arms added to `UnifiedBytecodeVirtualMachine`** (commit `f4ed0c9a`, PR #2730). Arithmetic, bitwise, comparison, and shift operators that previously fell through the VM dispatch table now have explicit fast-path arms. Rule 39 (binary-operator widening checklist, PR #2735/#2736) mandates that the compiler gate and VM eligibility gate stay in sync across all four affected surfaces.

- **Spread bulk-copy optimization attempt documented** (commit `af145ffe`, PR #2727). A dense-array spread pre-size and bulk-copy path was prototyped and A/B measured; the approach was found to be below threshold, so the decision and measurements are recorded rather than left as a recurring optimization candidate (rule 9b).

- **`docs/dreaming.md` rev 3 expands architecture direction** (commit `9308b48f`, PR #2725). Additions: `.NET Platform Advantage` section (JsValue struct, Span<JsValue>, NativeAOT, ValueTask zero-alloc async, meta-JIT, SIMD intrinsics); `Component 11 — Embedding / Host API` (CreateRealm, HostFunction bridge, first-class embedding contract); register-based VM directional note; positive completion conditions for each component.

- **`docs/dreaming.md` rev 4 adds Component 14 (Worker / Realm Fabric), Component 15 (Compilation Artifact Cache), JsValue struct layout, directional bytecode format, and Mermaid diagrams for components 3–6** (PR #2768). Worker / Realm Fabric: each Worker owns a dedicated `JsEngine` instance (realm-isolated); communication via structured clone only; `SharedArrayBuffer` opt-in requiring host capability grant. Compilation Artifact Cache: content-addressed by SHA-256(source text + realm fingerprint); cache hit skips lexer → parser → lowering → eligibility; primary enabler for cold-start < 5 ms p95 SLO on repeated-script workloads. JsValue struct layout: 24-byte tagged union — `Kind` (4-byte int enum, tags 0–9), `NumberValue` (8-byte double; Boolean stored as 0.0/1.0), `ObjectValue` (8-byte managed reference for String/BigInt/Symbol/Object). Directional bytecode encoding: `[Opcode:8][Dest:8][Src1:8][Src2:8]` fixed 32-bit word; Src1+Src2 as 16-bit constant pool index for literal loads; wide-instruction escape for large operands; requires ADR before wire-format freeze. Both new components are entirely directional; no implementation exists today.

- **Unified-bytecode production routing widened to admit array spread in array literals** (`[...x]`, `[a, ...x]`, `[, ...x]`). New `ArraySpread` opcode iterates the spread source via `EnumerateSpread` and pushes each element; `ArrayPushHole` standalone admission added for hole-before-spread patterns (`[, ...x]`). Holey and spread arrays are now accepted in call-argument and expression-value positions. Rule 40 (four-surface coupling checklist) documents the required update sites (PR #2750).

- **Compound property write eligibility and invocation coverage expanded** to `this`-base shapes and all 12 arithmetic/bitwise compound-assignment operators (+=, -=, *=, /=, %=, **=, &=, |=, ^=, <<=, >>=, >>>=). Theory tests added for both named and computed property paths with `this`-base; logical-assignment forms (`&&=`, `||=`, `??=`) confirmed declined with `PropertyWriteDependency`. Evidence recorded as ADR 0238 batch-4 deliverable (PRs #2755, #2758).

- **Unified-bytecode production routing widened to admit `&&`, `||`, and `??` expressions** via three new peek-semantics jump opcodes (`JumpIfShortCircuitFalse`, `JumpIfShortCircuitTrue`, `JumpIfShortCircuitNotNullish`). The compiler re-maps expression-IR `JumpIfFalse`/`JumpIfTrue`/`JumpIfNotNullish` ops to their unified counterparts via a backpatch map; the VM peeks TOS without consuming it, enabling spec-conformant short-circuit evaluation. Optional-chain `JumpIfShortCircuited` still declines as `OptionalChainDependency`. Decision recorded in ADR 0293 and rule 41 (PR #2761).

- **`object?` cursor and prototype locals narrowed to typed interfaces** in prototype traversal paths (PR #2783). `ObjectPrototype.cs` loop cursors and both `TryGetPrototype(object? candidate, …)` signatures narrowed from `object?` to `IJsObjectLike?`; `StandardLibrary.Helpers.HasProperty` `currentProto` local narrowed to `IJsPropertyAccessor?`. Advances the JsValue migration boundary described in ADR 0281 / rule 20.

- **`docs/dreaming.md` rev 5 fixes the greenfield diagram and adds three new architectural diagrams** (PR #2787). The top-level system flowchart's `Execution Engine` subgraph is relabeled from "4-tier" to "2 strata (greenfield target)" with Stratum 0 / Stratum F nodes (the migration-reality 4-tier diagram in §Greenfield target vs migration reality is unchanged). Added: startup cost breakdown diagram annotating cold-start phases and invariants (aligned with the < 5 ms p95 SLO); `JsValue ↔ .NET type conversion` flow diagram in component 11 showing which conversion paths are zero-alloc and which allocate a managed wrapper; host error translation path diagram tracing JS throw completion → VM unwind → host boundary → .NET `Exception` or `Task.Faulted`.

- **Bare `#region`/`#endregion` directives removed from 418 C# files** (commit `bc4d8907`, PR #2788). Unlabeled `#region` blocks used only to collapse using-directive groups in the IDE were stripped across the codebase; labeled `#region` blocks (101 regions in 16 files) are preserved. Net reduction: −836 code lines, −839 blank lines. Rule prohibiting bare `#region`/`#endregion` documented in csharp-editing rules (PR #2793).

- **Ternary edge-case: `Pop` and `Jump` admitted in `TryFindExpressionDecline`** (PR #2795). Added explicit `case ExpressionOpKind.Pop:` to the allowed-op group alongside `Jump` in `TryFindExpressionDecline`, ensuring the condition-discard op on both ternary paths is not misread as a decline signal. AC-2/AC-3 tests added: consume-semantics regression (truthy/falsy branches produce correct results sequentially, ruling out peek-semantics regression) and nested ternary all-combinations test (`c1 ? c2 ? a : b : d`). Rule 43 updated.

- **Unified-bytecode production routing widened to admit multi-hop optional named chains** (`a?.b.c`, `a?.b?.c`) (PR #2804, ADR 0298, rule 42). All optional hops lower to `JumpIfNullishReplaceUndefined(chain-end)` pointing at the same chain-end PC, so nullish anywhere short-circuits to `undefined` with no new opcode or sentinel array. Real-`undefined` non-nullish intermediates still throw on the following plain read (`a?.b.c` with `b === undefined` still TypeErrors; only `a?.b?.c` skips). Decision recorded in ADR 0298; rule 42 updated (PR #2805).
- **Unified-bytecode production routing widened to admit optional call-chain forms** (`a?.b.c()`, `a?.b?.c()`, `a?.b[k]()`) by lowering Cases 4/5/6 in call-target preparation through existing jump and call-target-preparation opcodes (`JumpIfNullishReplaceUndefined`, `PrepareNamedCallTarget`, `PrepareNamedOptionalCallTarget`, `PrepareComputedCallTarget`) (PRs #2814/#2832, issues gh2806/gh2828, ADR 0301).
- **Unified-bytecode production routing widened to admit direct member logical assignment** (`box.value &&= y`, `box.value ||= y`, `box.value ??= y`, `box[key] &&= y`, `box[key] ||= y`, `box[key] ??= y`) through compiler lowering and existing member write opcodes (ADR 0302 + gh2844 follow-up). Optional/private/super/deeper member chains and non-member forms remain explicit declines pending dedicated follow-up slices.
- **Unified-bytecode production routing widened to admit nested named property assignments and updates** (`box.child.value = y`, `++box.child.count`) when the root and intermediate receiver chain are activation-resolved, non-optional, non-private named reads. ADR 0308 / PR #2897 keeps nested compound/logical assignment chains, computed-expression keys, optional chains, `super`, private names, calls, and dynamic lookup as explicit future boundaries.
- **Unified-bytecode production routing widened to admit ordinary named/computed property delete and the first optional-chain delete lanes**. ADR 0309 / PR #2900 admitted ordinary delete (`delete box.value`, `delete box[key]`, `delete box.child.value`) through owned delete opcodes and descriptor-aware strict/sloppy behavior. The later A32 proof in `docs/bytecode-progress.md` admits terminal optional named deletes, non-terminal optional named deletes, terminal optional computed deletes, and optional computed-read receiver plus terminal computed delete while preserving private names, `super`, dynamic identifier delete, proxy-sensitive lookup, and unsupported key/receiver payloads as explicit declines.
- **Unified-bytecode production routing widened to admit optional named-then-computed read continuations** such as `a?.items[left + right].value`. ADR 0311 / PR #2898 proves the first optional hop short-circuits before computed-key evaluation while ordinary trailing named reads stay VM-owned; optional trailing computed hops, writes/updates/deletes, calls, `super`, private names, dynamic lookup, and unowned computed-key payloads remain declined.
- **Unified-bytecode production routing widened to admit nested named receiver computed delete** (`delete box.child[key]`). PR #2931 composes the existing `GetNamedProperty` receiver hops with `DeleteComputedProperty`; ADR 0316 / PR #2932 kept optional receiver chains, richer computed-key payloads, dynamic lookup, private names, and `super` as pre-VM declines until the later A32 optional-chain delete slice narrowed that boundary.
- **Unified-bytecode production routing widened to admit descriptor-backed assignment destructuring** through `ApplyBindingTarget` (PR #2941, ADR 0318). The VM owns dispatch, stack shape, slot/environment synchronization, and binding-target descriptor invocation for expression-level assignment destructuring; declaration driver shapes and unsupported destructuring neighbors still decline before VM execution.
- **Unified-bytecode resumable sync-generator `yield*` now executes through the VM-owned `YieldStar` route** (PR #2948), with the boundary documented in PR #2950 / ADR 0277. The accepted lane covers sync generator delegated `.next()`, `.return(value)`, and `.throw(value)` resume behavior; async-generator `yield*`, awaited delegated sources, and adjacent unsupported expression payloads remain explicit declines.
- **Resumable unified bytecode widened again on June 5, including the first bounded async-generator route and newer resumable body shapes.** PR #3118 admits regex literals between suspension points; PR #3122 adds the missing `TdzHeadInit` resumable handler; PR #3123 hardens the for-of driver guard so suspending/nested try/finally correctly declines instead of misrouting; PR #3116 preserves const assignment errors on the resumable lexical-slot path. PR #3142 / gh3135 then models the first `async function*` `EvaluateResumable` production route for simple-parameter direct-yield bodies. Follow-on docs in `docs/bytecode-progress.md` and `docs/unified-bytecode-expansion-contract.md` record resumable dynamic free writes and compound/logical writes, safe root hoisted function declarations, constructor/default-constructor class expressions (PR #3195), public non-computed instance fields (PR #3209), public non-computed static fields, public non-computed instance accessors, narrow private instance-field / private method class-literal subsets (PRs #3201, #3203, #3208), async-generator `yield*` for both direct and awaited delegated sources, resumable `yield*` state-slot layout, and simple/optional try-catch across suspension as admitted. Awaited delegated-source async-generator `yield* await ...` now emits the source expression followed by `AwaitValue` and the VM-owned `YieldStar` driver. Static blocks, computed members, member-`super`, activation-capturing field initializers or accessor bodies, `extends` expressions that read resumable activation slots, destructuring catch bindings, async captured-local function literals, lexical/private closure contexts, and the remaining B36 declaration-hoisting residues remain explicit pre-VM decline boundaries; B36 is tracked as [gh3238](https://github.com/asynkron/Asynkron.JsEngine/issues/3238).
- **Declaration instruction coverage has moved from stale compiler declines into VM-owned lowering paths** (PR #2951, rule update PR #2952, follow-up June 2026). Function-scoped `FunctionDeclarationInstruction` now compiles as a hoisted no-op on the production route, with fast activation setup installing callable values before VM execution; descriptor-backed runtime declarations lower to `DeclareFunction` when their surrounding block environment shape is admitted. `ClassDeclarationInstruction` is VM-owned through `DeclareClass`, with environment-backed lexical declaration installation handled inside the unified VM.
- **The June 8 proof manifest makes the finite bytecode inventory executable instead of narrative-only.** `docs/plans/bytecode-proof-manifest.json` is now verified by `BytecodeProofManifestTests` and keeps source-presence/source-absence rows for A51, B24h, B36, E4, E5b-E5e, E6, and terminal dynamic residue. `docs/plans/bytecode-burndown-checklist.md` records `137 / 161` complete with A+B+C+D at `127 / 146`, Phase E at `5 / 10`, a resumable opcode gap inventory of `5`, and instruction gaps at `0`; these are checklist/proof signals, not runtime parity claims.
- **The remaining unified-bytecode work is now a finite boundary-mapping problem, not a missing-switch-arm problem.** `docs/bytecode-progress.md` shows the production route is active for admitted ordinary sync, selected resumable generator/async/async-generator shapes, and many benchmark-profile shapes, while zero-hit rows still identify workload shapes that did not enter `unified-bytecode-production-fast-path`. `docs/unified-bytecode-expansion-contract.md` keeps the source-of-truth gate view: every current decline code has a ledger row, the `UnifiedBytecodeOpCode` inventory is expected to stay VM-covered, and PR #3138 / gh3134 closed the stale `UnifiedBytecodeCompiler.TryCompile` / `UnsupportedPlanShape` umbrella by promoting compiler failure templates into named A51a-A51m plus B47a owner leaves. Current proof-manifest owners now admit the B24h and B36 static-block-super property route rows, while keeping runtime-source direct eval and the surrounding class-definition environment/static-block residues open until each source shape has focused route or no-route proof. E5b-E5e likewise remain open for classified runner/exclusion rows until exact fallback-retirement shapes have focused semantic proof.
- **Module export and async-iteration cleanup have narrowed two host-facing owner surfaces, but they are not broad module or async parity claims.** `JsEngine.CreateLiveBinding(...)` now returns a `JsValue` for direct re-export and export-star live bindings, while `EvaluateExportDefault(...)` / `EvaluateExportDefaultDeclaration(...)` still own the default-export binding shapes that need focused proof before the roadmap can call the module surface `JsValue`-native end to end. `IterationHelper` remains the async iterator protocol helper owner after obsolete wrapper cleanup: `GetAsyncIteratorCore(...)`, `IteratorNextCore(...)`, and the for-await call sites in `JsEngine.cs` are the current evidence boundary for protocol/allocation work.
- **ADR 0373 supersedes the attempted async-function declined-runner bridge retirement.** PR #3480 first targeted `TypedAstEvaluator.AsyncFunctionInvoker`, but the June 8 quality repair kept `CreateClassifiedAsyncDeclinedBodyRunner(...)` and the async `.ExecuteAsyncStep(...)` path as classified open residue because route-ineligible async functions must still complete through the legacy runner. Future E5 work must widen exact async-function route parity before removing those anchors; rejecting declined async bodies is not an accepted fallback-retirement strategy.
- **Map/Set IR plain-method dispatch now has a measured fast path plus an identity guard** (PR #2946, rule/ADR follow-up #2949). The `mapset` selected-profile row improved from `asynkron_ms=2227` / `jint_ms=787` to repeated post-change rows around `asynkron_ms=886-931` / `jint_ms=703-759`, a documented 58.6% Asynkron median reduction. This is not parity: the latest evidence still shows Jint about 1.21x-1.26x faster, and follow-up issue [gh2954](https://github.com/asynkron/Asynkron.JsEngine/issues/2954) tracks the remaining measured gap.
- **Class-constructor slot storage and functioncall dependency scans have recent measured wins, but both remain follow-up performance packets rather than parity claims.** PR #3505 kept `SyncFunctionInvoker`-owned reusable slot storage scoped to bounded class constructors after focused `classdef` A/B rows improved from about 4399 ms unpatched to about 2092 ms patched; `docs/performance/classdef-production-slot-storage-cache.md` keeps the remaining constructor/super dispatch, property-store, and `Array.map` callback costs separate, with follow-up [gh3531](https://github.com/asynkron/Asynkron.JsEngine/issues/3531) tracking a fresh residual-owner profile. PR #3528 / ADR 0378 caches plan-pure production UBC dependency-scan facts on `ExecutionPlan`, improving focused `functioncalls` Asynkron rows from average 6043 ms to 5179 ms while preserving descriptor/runtime/call-argument boundaries; `docs/performance/functioncalls-plan-dependency-scan-cache.md` records the evidence, and follow-up [gh3530](https://github.com/asynkron/Asynkron.JsEngine/issues/3530) tracks the remaining production call-dispatch gap. Jint remains faster in both profiles.
- **Ordinary sync production pre-gates moved onto a descriptorized activation contract** (PR #2855). `SyncFunctionInvoker` now builds a `UnifiedBytecodeProductionActivationDescriptor` and shares `TryFindOrdinarySyncActivationDecline(...)` with `UnifiedBytecodeProductionEligibility` before plan-shape inspection. The current stable activation-blocker taxonomy is explicit: arrow lexical `this` / `new.target` and class-constructor activation each map to their own `UnifiedBytecodeProductionDeclineCode`; those invocation-dependent declines stay out of structural plan caching.
- **Unified-bytecode production routing widened to admit class literal values** (PR #2858). `ExpressionOpKind.LoadClassLiteral` now lowers to `UnifiedBytecodeOpCode.LoadClassLiteral`, and `UnifiedBytecodeVirtualMachine` executes it through `TypedAstEvaluator.CreateClassValueFromLiteral(...)` with the caller environment supplied by the sync bridge. This removes class literals from the generic literal/spread decline lane without reintroducing `ExpressionProgram` or AST-eval fallback for class semantics.
- **`SymbolHybridDictionary` loops consolidated to `TryFindEntry`** (PR #2816) to reduce duplicated lookup-loop code in one maintained hot-path surface. Treat this as maintainability evidence; profile/benchmark proof is still required before broader performance claims.
- **Performance SLO baseline infrastructure is now committed, but parity is not claimed.** `tools/perf-slo-baseline.md` records ProfileRunner baselines for `startup` (~4.80 ms avg) and `microtask` (~8.00 ms avg per 1 000 jobs), and `make slo-gate` rechecks those profiles via `tools/check-slo-gate`. ADR 0310 / PR #2908 keeps the gate as committed-baseline regression evidence only; PR #2930 adds p95 target-status and same-run Node.js comparison columns as non-failing evidence. Startup now has a maintained evidence packet at `docs/performance/startup-slo-evidence.md`; its current p95 remains over the `< 5 ms` target, so the startup SLO stays directional / Prototyped. Avg-ms baselines are still not p95 proof, and Node.js-competitive SLOs stay directional until a dedicated evidence packet attaches the matching measurement shape.

Architecture direction is tracked in docs rather than as runtime parity claims: unified-bytecode primary sync-route coverage is recorded (PR #2644), the ordinary sync `this`-binding route is recorded in ADR 0279 (issue #2633), its resumable async/generator counterpart accepting `this`-dependent suspendable functions is recorded in ADR 0283 (issue #2675), and the typed-AST/"dreaming" target is refined in `docs/dreaming.md` — a 4-tier execution model (PR #2647) followed by a self-critique revision (PR #2663), with tier-numbering disambiguation captured as rule 14 (PR #2650). These describe a staged migration with allocation budgets and escape hatches, not current parity.

Conformance against Test262 is tracked via a custom testrunner with baselines in `.testrunner/`. Most reported failures are crash collateral rather than true correctness gaps; real correctness failures are typically under 20.
