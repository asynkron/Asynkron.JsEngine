## Diagnosis (2026-01-22)

**Summary:** DataView constructor ordering and instance representation diverge from spec (premature prototype access, missing NewTarget/detach checks, and non-object DataView instances), causing TypeError/RangeError expectation failures and prototype/extensibility assertions to break.

**Error Pattern:**
```
Asynkron.JsEngine.ThrowSignal: Unhandled JavaScript throw: Expected a RangeError but got a Test262Error
Asynkron.JsEngine.ThrowSignal: Unhandled JavaScript throw: Expected a TypeError but got a Test262Error
Asynkron.JsEngine.ThrowSignal: Unhandled JavaScript throw: 'TypeError': 'Object.getPrototypeOf called on null or undefined'
Asynkron.JsEngine.ThrowSignal: Unhandled JavaScript throw:
```

**Analysis:**
The failing tests cluster around spec-mandated constructor ordering and object-ness. `Reflect.construct` pre-resolves `newTarget.prototype`, so user-defined getters run before DataView validates `byteOffset`/`byteLength`; this flips errors from expected `RangeError`/`TypeError` to `Test262Error` (assert.throws failures). The DataView constructor also accepts calls without `new` (treats `NewTarget` as the constructor) and evaluates `byteOffset` before checking `NewTarget`, so side-effecting `valueOf` runs when it must not. Detached/resized buffer cases show missing `IsDetachedBuffer` checks (both initial and post-OrdinaryCreateFromConstructor re-check), letting detached buffers through. Finally, `JsDataView` is not `IJsObjectLike`, so `Object.getPrototypeOf`/`Object.isExtensible` treat normal `new DataView(...)` results as non-objects, yielding `Object.getPrototypeOf called on null or undefined` and `false` extensibility.

**Fix Direction:**
Align `DataViewConstructor` with the spec algorithm: throw on `NewTarget` undefined before argument conversions, use `ToIndex` for `byteOffset`/`byteLength`, validate against the initial buffer length before `GetPrototypeFromConstructor`, and add detached-buffer checks both before and after prototype resolution. Avoid premature `ResolveConstructPrototype` in the `Reflect.construct` path for DataView (or make the constructor use the provided `this` without re-resolving the prototype). Ensure DataView instances are object-like by either wrapping the internal `JsDataView` in a `JsObject` even for the default constructor or making `JsDataView` implement `IJsObjectLike`/`IExtensibilityControl` so `Object.getPrototypeOf` and `Object.isExtensible` work as expected.
